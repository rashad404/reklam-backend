# Reklam.biz product standard

Name the user task and concrete friction before changing a feature. Follow it through every affected list, form, API, status, report, locale and device. Preserve the logo and red identity; use restrained neutral surfaces and compact working screens. No invented metrics, testimonials, reach, guarantees or unsupported feature claims.

Use realistic fixtures including long Azerbaijani/Russian labels, many records, missing images, pending/rejected states, no traffic, expired authentication and failed requests. A failed request is not zero data. Money operations are excluded from the current roadmap; do not imply they are ready.

Verify UI changes in a rendered browser at 320px, 390px and desktop, with keyboard and both themes. Exercise controls and persistence; screenshots and compilation alone do not prove a journey. Add regression tests for meaningful behavior. Record actual checks and environment, and name unverified production dependencies. Documentation-only changes need no runtime tests.

Public content should explain actual tasks. Use localized metadata, canonical language URLs and private workspace noindex. Use natural Azerbaijani, full language characters and ASCII punctuation. Keep dependencies and page weight purposeful. Do not claim ranking or field performance from lab checks.

Fix problems within the authorized task before calling it complete. Store detailed evidence in knowledge plans/audits. These requirements do not introduce another approval step. Do not spawn agents unless separately authorized.
